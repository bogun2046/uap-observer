# G5 冻结验收用例

冻结编号：`G5-FROZEN-20260816-01`

## G5-01 Collector 接口边界

给定一个合法 RSS collector payload，fetch、parse、normalize、persist 四阶段可以独立调用；阶段之间只通过版本化结构传递数据，异常不会绕过 source run 记录。

预期：接口契约测试通过；Collector 不直接写 public，不把原始正文写入日志。

## G5-02 固定 RSS 快照确定性

对同一固定快照执行两次解析。

预期：条目字段、规范化 URL、来源条目 ID、排序和计数完全一致；同一快照哈希被记录。

## G5-03 幂等与去重

对包含重复链接、重复来源条目 ID、追踪参数变化和同标题不同链接的快照执行持久化。

预期：同一来源同一 canonical locator 只有一条 artifact；重复运行新增数为 0；同标题不同链接不被错误合并。

## G5-04 source run 与任务状态

通过 `fetch_source` 任务执行一次成功采集，并核对 `ops.jobs`、`ingest.source_runs`、`ingest.artifacts` 和来源关联。

预期：任务与 source run 一对一；开始/结束时间、计数、结果和 job ID 完整；每条落库数据可追溯到来源与采集批次。

## G5-05 HTTP 与运行结果分类

分别注入 304、空响应、403、429、连接超时、500 和 503。

预期：304 为 `not_modified`，空响应为 `empty`；403 为授权失败并停止该次继续请求；429、超时和 5xx 按冻结重试策略进入 retry/dead 路径；所有失败均产生 source run。

## G5-06 限速、冷却与健康检查

连续触发同一来源的速率限制和失败，随后查询健康检查结果。

预期：请求间隔不低于配置值；冷却期间不产生违规请求；健康状态包含最近成功、连续失败和冷却截止时间。

## G5-07 来源故障隔离

同时调度一个正常 RSS 来源和一个持续返回 5xx 的来源。

预期：故障来源按自身策略重试或进入死信；正常来源成功完成，不能被共享状态或全局异常阻断。

## G5-08 可追溯性与权限

从一条持久化条目反查 source、source config version、source run、job 和 artifact；使用公开角色尝试读取 ingest 原始记录。

预期：链路完整且无孤儿；公开角色不能读取 ingest 原始数据；Collector 使用的业务角色符合 G3/G4 权限矩阵。

## 门禁

G5-01 至 G5-08 必须全部通过，并同时满足 Ruff、mypy、全量测试、迁移链、权限检查和证据清单逐项哈希校验。否则 WP5 不通过，WP6 门禁关闭。
