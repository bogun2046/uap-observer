## 独立性要求

- 使用全新数据库、对象存储、业务角色和脱敏固定 Provider 响应。
- 使用真实 `uap_worker`、model-governance 和 public reader 角色，不以超级用户替代权限验证。
- 独立保存迁移输出、任务/attempt/model-run/result ID、对象清单、哈希、日志和逐项证据。
- 独立验收人员不得修改实现代码；整改后必须形成新提交、新清单和新 required CI run。
- 验收必须覆盖成功、重复、版本切换、结构化失败、认证失败、限流、超时和租约失效路径。

## 冻结验收用例

### G7-01 输入边界与全链路追溯

合法任务只能引用已存在的 `document_version_id`、允许的任务类型和已激活的 Prompt 版本，并通过 WP4 的 attempt/lease 执行。每条 `model_run` 和 `analysis_result` 均可反查任务、文档版本、Prompt 版本和输入哈希；非法 payload 不得发起 Provider 调用。

### G7-02 结构化输出校验

翻译、摘要、分类、实体提取和主张提取分别使用版本化 Schema。黄金测试集的合法响应通过率为 100%；缺字段、类型错误、未知高风险字段或不符合任务类型的响应必须被拒绝，写入结构化校验错误，不得生成成功分析结果。

### G7-03 追加式结果与版本治理

相同输入、Prompt 版本、模型版本和任务类型重复执行时只能产生一个有效结果；更换模型或 Prompt 版本只能追加新 `model_run`/`analysis_result`，不得更新、删除或清空旧结果。历史结果可独立读取并保留完整哈希。

### G7-04 Provider 错误与任务状态闭环

401/403 必须停止继续调用并形成终止错误；429、连接超时和 5xx 必须按冻结重试策略进入 `retry_wait` 或 `dead`；Schema 失败和预算超限必须形成可审计失败结果。所有路径都必须结束当前 attempt，不能遗留 `running` 任务。

### G7-05 模型调用对象与哈希一致性

输入摘要、Provider 原始响应和结构化结果分别按规定域保存。数据库中的对象登记、内容哈希、字节长度和对象存储实际内容必须一致；失败回滚或补偿不得留下未登记 model-io 对象，重复扫描必须幂等。

### G7-06 安全与最小权限

model-governance 只能访问模型治理所需表和 model-io 对象；普通 Worker 不能写 public 或 audit；public reader 不能读取 Prompt 原文、模型原始响应、API Key 和内部错误。日志和 CI 产物不得出现密钥、原始响应或敏感正文。

### G7-07 费用、资源与调用指标

每次调用记录输入/输出 Token、费用、币种、开始/结束时间、Provider 响应 ID 和错误码。超时、输入/输出大小、调用次数或预算超限必须在 Provider 边界被拒绝并闭环；重复任务不能重复计费或产生第二个有效结果。

### G7-08 交付物一致性与回归

G6、WP2–WP6 静态检查、迁移链、权限探针和 G7 运行态探针全部通过；最终提交、R2 以前的固定证据、G7 新证据、清单逐项哈希和外层锚点一致。Draft PR 的 `quality`、`security`、`integration`、`gate` 必须全部成功。

## 验收证据字段

- 最终提交、迁移头、容器镜像、Provider 脱敏响应和夹具哈希。
- 每个用例的操作、预期、实际结果及任务/attempt/model-run/result/object ID。
- Schema 校验报告、权限查询、对象清单、日志脱敏检查、费用统计和 CI run。
- 缺陷编号、整改轮次、验收人角色、验收时间、证据清单及外层 SHA-256。
- 最终结论：`G7 通过，WP8 开启` 或 `G7 不通过，WP8 关闭`。
