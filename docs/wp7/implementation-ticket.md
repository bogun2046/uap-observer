## 输入与范围

本工作包负责将翻译、摘要、分类、实体提取和主张提取实现为可追溯、可重试、可审计的独立 AI 任务。每次调用必须形成模型运行记录，并将结构化结果追加保存；不得把 AI 结果直接写入公开读模型。

输入至少包括：`document_version_id`、任务类型、Prompt 版本、模型 Provider、模型名称、输入对象或输入哈希，以及 WP4 的 `job_attempt_id` 和租约信息。调用边界只能读取已经登记的文档派生数据和必要的证据定位，不得根据 URL 访问外部网络。

## 交付内容

- AI 任务契约和任务类型白名单。
- Prompt 版本读取与内容哈希校验。
- Provider 适配器和统一响应接口。
- Pydantic 结构化输出 Schema 及版本化校验。
- `ops.model_runs` 的追加式调用记录。
- `core.analysis_results` 的追加式结构化结果记录。
- model-io 对象的输入/原始响应保存和哈希校验。
- 调用失败、校验失败、超时、401/403 和预算超限的状态映射。
- Token、费用、币种、延迟和错误码指标。
- 黄金测试集、脱敏固定响应和确定性回归测试。
- 真实 PostgreSQL、对象存储和 `uap_worker` 运行态探针。

## 不做事项

- 不实现 Claim、Evidence、Entity、Relation 的审核或合并界面；这些属于 WP8/WP9。
- 不允许模型结果直接进入 `public` Schema 或公开 API。
- 不覆盖已有模型运行和分析结果，不做历史数据迁移。
- 不在本工作包中新增外部 Provider 凭据或把密钥写入代码、日志、测试夹具和镜像。
- 不绕过 WP4 的任务租约、重试、死信和 Outbox 约束。

## 实现约束

1. `ops.model_runs` 必须记录文档版本、任务类型、Prompt 版本、Provider、模型、输入哈希、请求/响应对象、状态、Token、费用和错误摘要。
2. `core.analysis_results` 只能追加；同一模型运行与结果类型不得重复登记，模型或 Prompt 版本变化只能产生新结果。
3. Provider 返回内容先通过对应 Schema，再写入结构化结果；失败必须保留可审计的 `invalid` 或 `failed` 记录及校验错误，不得伪造成功结果。
4. 401/403 必须停止当前调用链的继续尝试，并进入明确的终止状态；429、超时和 5xx 遵循 WP4 重试策略。
5. 日志只能记录任务 ID、运行 ID、哈希、计数、耗时、费用和净化后的错误码，不得记录 API Key、原始响应或敏感正文。
6. 结果与任务完成必须在同一事务边界内闭环；租约失效时模型运行和任务完成一起回滚或进入可重试状态。
