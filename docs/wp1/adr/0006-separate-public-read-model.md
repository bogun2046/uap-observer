# ADR-0006：独立公开读模型

- 状态：Accepted for G1
- 日期：2026-08-11

## 背景

直接从内部表过滤“已审核”容易因查询遗漏暴露原始正文、模型响应或驳回数据，也让公开查询受内部复杂 Schema 影响。

## 决策

审核通过后，由四类真实外键授权表分别授权文档版本、Claim、实体和关系；授权记录以复合外键证明 decision、review case 和 subject 一致。独立 Publisher 进程以 `uap_publisher` 凭据调用发布模块，只把持有有效授权的最小必要字段事务性投影到 `public` Schema，并通过 `public.document_entities` 保存详情页实体关联及其已授权依据。普通 Worker 无 public 权限。公开 API 使用独立 `uap_public_reader` 账号，只能读取该 Schema。撤回由 Publisher 删除/失效对应公开投影及关联，但内部审核和审计保留。

## 后果

- 安全边界可由数据库权限直接验证，公开查询简单且可优化。
- 需要发布任务、缓存失效和可重建机制。
- 内部数据变更不会自动公开，必须经过明确审核和发布事件。

## 未采用方案

- 内部表上的普通视图：底层权限和字段演进容易造成意外暴露。
- API 代码中临时过滤：每个 endpoint 都可能重复犯错，无法形成强隔离。
