# ADR-0004：持久化任务、租约与事务 Outbox

- 状态：Accepted for G1
- 日期：2026-08-11

## 背景

当前多个处理状态堆叠在 `news`，不能通用表达租约、尝试、退避、死信和跨步骤可靠触发。

## 决策

所有异步动作进入 `ops.jobs`，每次执行追加 `job_attempts`；普通 Worker 只领取采集/提取/AI/知识任务，Publisher 只领取发布/撤回/缓存失效任务，两者分别使用 PostgreSQL 原子领取、有期限租约、独立 job-type 白名单和独立凭据。领域事务与后续事件在同事务写入 `outbox_events`，分发器再创建下游幂等任务。超过上限进入 `dead_letters`。

## 后果

- 业务表不再承担任务状态；相同框架覆盖采集、提取、AI、发布。
- 系统按“至少一次执行 + 业务幂等”设计，不承诺不现实的端到端 exactly-once。
- WP4 必须冻结 403、429、5xx、超时和授权失败的不同策略。

## 未采用方案

- 进程内队列：重启丢失，无法审计。
- 只使用外部消息代理：仍需解决业务提交和消息发送的双写问题；初始阶段 PostgreSQL 队列足够。
