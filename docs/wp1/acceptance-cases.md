# WP1 / G1 冻结验收用例

冻结编号：`G1-FROZEN-20260811-01`  
冻结时间：2026-08-11（Asia/Shanghai）  
状态：已冻结；后续只补实际结果和证据。标准变更必须创建新版本并说明原因。

## G1-01 数据分层明确

- 操作：追踪一个来源响应从采集、原始存储、正文提取、AI、审核到公开 API 的全链路。
- 预期：原始数据、派生数据、审核数据、公开数据分别落在 `ingest`、`core/ops`、`audit`、`public` 边界；每次跨层有明确写入者和门禁。

## G1-02 业务记录与任务状态解耦

- 操作：检查目标 ER 和任务状态机入口。
- 预期：`news` 不再作为目标模型；文档业务事实保存在 `core`，采集/提取/AI/发布状态保存在 `ops.jobs` 和 `ops.job_attempts`，业务表不增加工作队列状态列。

## G1-03 主键、唯一约束与所有者完整

- 操作：逐表检查数据字典。
- 预期：每张表均明确 Schema、用途、主键、自然唯一约束、外键策略、数据所有者和保留策略；关系两端使用真实外键，不使用无法约束的多态整数 ID。

## G1-04 AI 结果多版本追加

- 操作：模拟同一文档以不同模型/Prompt 重跑两次。
- 预期：两次 `model_runs` 和 `analysis_results` 都保留；由显式选择记录决定当前候选版本，禁止覆盖旧结果；模型输出不能直接写入 `public`。

## G1-05 公开角色最小权限

- 操作：按权限矩阵检查公开 API 数据路径。
- 预期：公开角色只能读取 `public` Schema 的明确视图/表；无法读取原始正文、原始对象、模型原始响应、Prompt、Token/费用、内部错误和审核员身份信息。

## G1-06 PostgreSQL 为唯一权威数据模型

- 操作：检查 ADR、模块边界和目标目录约定。
- 预期：PostgreSQL Schema 是唯一目标模型；SQLite 与 `supabase/schema.sql` 仅作为迁移输入或历史基线，不能继续演进为并行生产 Schema。

## G1-07 不存在两套独立迁移源

- 操作：检查迁移 ADR 和后续 WP2/WP3 接口。
- 预期：只有一条 Alembic 迁移链可部署 DDL；ORM/映射代码通过一致性测试跟随迁移，不生成第二条权威迁移；禁止复制迁移文件到包内另一目录。

## G1-08 架构交付物完整且互相一致

- 操作：交叉核对 C4、ER、数据字典、模块依赖、OpenAPI、权限矩阵、ADR 和服务目标。
- 预期：名称、职责、数据路径和权限没有冲突；API 只返回公开 DTO；性能、可用性、RTO/RPO 指标可在后续工作包验证。
