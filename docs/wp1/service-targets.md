# 性能、可用性与恢复目标草案

这些指标在 WP1 作为可测试目标冻结，WP2 建立测量环境，WP3/WP12 分别验证恢复与生产能力。业务负责人可在 G1 验收时调整，但必须留下版本记录。

## 1. 服务等级目标

| 能力 | 指标 | 目标 | 测量窗口 |
|---|---|---:|---|
| 公开站点/API 可用性 | 成功响应率 | ≥ 99.9% | 月度，排除批准维护窗 |
| 审核后台可用性 | 成功响应率 | ≥ 99.5% | 月度 |
| 公开文档列表/详情 | p95 / p99 | ≤ 300 ms / 800 ms | 服务端，缓存未命中 |
| 公开全文搜索 | p95 / p99 | ≤ 500 ms / 1200 ms | 10 万公开文档基准 |
| 审核队列查询 | p95 | ≤ 500 ms | 10 万候选基准 |
| 审核决定提交 | p95 | ≤ 800 ms | 含审计与 Outbox 提交，不等待发布 |
| 发布新鲜度 | 审核通过至 public 可见 p95 | ≤ 2 分钟 | 正常队列负载 |
| 采集调度延迟 | 到期至任务创建 p95 | ≤ 1 分钟 | 正常负载 |
| Worker 租约恢复 | 进程退出至可重领 | ≤ 2 × 任务租约 | 按 job type 配置 |

错误预算：公开服务月度 0.1%，审核后台月度 0.5%。外部来源和模型 Provider 不计入公开服务可用性，但其失败必须计入采集/模型成功率指标。

## 2. 容量基线

- 初始设计容量：100 个来源、100 万文档、每文档 10 个版本、1000 万 Claim/证据、每分钟 1000 个排队任务。
- PostgreSQL 连接：API、Worker、发布器分别使用连接池和上限，系统总连接保持在实例上限的 70% 以下。
- 大于 256 KiB 的原始/派生正文默认进入对象存储；数据库保存元数据、哈希、定位和受控摘录。
- `ops.job_attempts`、`audit.audit_events` 按月分区的阈值在单表 5000 万行或 100 GiB 前评审。
- 搜索在 100 万公开文档内优先 PostgreSQL FTS；若连续两周无法满足 p95，再通过 ADR 评估独立搜索服务。

## 3. RTO/RPO

| 数据/服务 | RPO | RTO | 恢复方式 |
|---|---:|---:|---|
| PostgreSQL 生产数据 | ≤ 15 分钟 | ≤ 60 分钟 | 连续 WAL/PITR + 每日全备 |
| 原始/派生对象 | ≤ 15 分钟 | ≤ 4 小时 | 版本化对象存储 + 跨故障域复制/清单核对 |
| 审计数据 | ≤ 5 分钟 | ≤ 60 分钟 | WAL/PITR；优先恢复且禁止跳过 |
| 公开读模型 | ≤ 24 小时的数据源备份；运行时可重建 | ≤ 30 分钟 | 从审核授权重建，期间提供上个 release |
| 公开静态资产 | 上个成功 release | ≤ 15 分钟 | 回滚到不可变 release |
| 密钥/配置 | ≤ 24 小时 | ≤ 60 分钟 | 密钥管理器版本和 IaC 恢复 |

“RPO 0”不作为当前承诺；审核通过后的 Outbox、数据库事务和对象清单用于减少逻辑丢失，但灾难恢复仍以上表为验收标准。

## 4. 备份与恢复验证

- 每日 PostgreSQL 全备、连续 WAL；每周自动恢复到隔离实例并运行 Schema、行数、外键和抽样内容哈希检查。
- 对象存储每日生成清单；恢复演练通过 `ingest.artifact_versions.stored_object_id -> core.stored_objects.id` 关联，将 `core.stored_objects.object_key/content_sha256/byte_length` 与对象存储清单逐项核对。
- 每季度执行一次完整应用恢复和公开投影重建；每次重大 Schema 变更前后执行按需恢复演练。
- 备份加密、不可由生产应用删除；恢复操作者与生产管理员职责分离。

## 5. 监控指标

- API：请求率、错误率、延迟、公开查询慢 SQL、连接池饱和度。
- 来源：成功/304/空/403/429/5xx/超时、连续失败、冷却时间、数据新鲜度。
- 任务：队列深度、最老任务年龄、租约超时、重试分布、死信数量、Outbox 延迟。
- AI：401/403、429、5xx、Schema 通过率、Token、费用、严重事实错误人工标记。
- 发布：待发布数量、投影构建时长、缓存失效时长、撤回传播时间。
- 数据：外键违规、孤立对象、重复哈希、未绑定证据 Claim、public 与授权不一致数。

## 6. Go/No-Go 最低条件

- 所有 SLO 有自动化测量方法和 Dashboard owner。
- WP3 完成独立实例恢复并满足 RPO/RTO 演练结果。
- WP10 在约定容量样本上达到公开 API/搜索性能目标。
- WP12 生产切换前实际执行备份恢复、公开 release 回滚和旧系统回切。
