# G2 冻结标准安全补充 A1

- 补充编号：`G2-FROZEN-20260812-01-A1`
- 原冻结标准：`G2-FROZEN-20260812-01`
- 触发缺陷：`G2-D01`
- 生效日期：2026-08-12（Asia/Shanghai）
- 门禁：本补充不代表 G2 通过；WP3 继续关闭

## 变更理由

首轮独立验收确认原固定 MinIO 构建处于已知 High 漏洞影响范围，且该
上游已停止维护。继续要求同一产品名称会与安全门禁冲突，因此只替换
产品约束，不降低对象存储功能、密钥隔离或验收强度。

## 补充后的冻结要求

1. G2-01、G2-02 和 G2-05 中的“MinIO”统一解释为“受维护、固定版本与
   摘要的 S3 兼容对象存储”；仍须自动建立 `raw`、`derived`、`model-io`
   和 `public-assets` 四个私有 bucket。
2. Python 必须为 3.12.13 安全修复线，PostgreSQL 必须为 16.14；实际部署
   镜像不得包含已知 High 或 Critical 漏洞。
3. CI 必须扫描最终应用镜像、实际 PostgreSQL 运行镜像和对象存储镜像，
   使用 `HIGH,CRITICAL` 且 `exit-code=1`；不得通过忽略未修复漏洞绕过。
4. 应保留扫描器自身的固定版本、镜像摘要和本地预检来源，并通过失败
   注入证明任一安全 job 失败时汇总 `gate` 同步失败。
5. 原 G2 的空 volume、密钥、日志、镜像历史、required check 和 staging
   连续部署要求全部继续有效。
